Correct Implementation Model

Instead of:

IF safe → GO
IF missing → HOLD
IF unsafe → ABORT

Use:

scores = {
  GO: 0.00,
  HOLD: 0.00,
  ABORT: 0.00
}

Then every signal changes the scores.


---

Example

User asks for legal contract review.

Signals:
- task clear: +GO
- high-stakes legal: +HOLD
- no source document uploaded: +HOLD
- safe request: +GO
- requires citations: +HOLD
- no illegal intent: -ABORT

Result:
GO:    0.35
HOLD:  0.60
ABORT: 0.05

Collapsed state:
HOLD

Replit Prompt Addition

Upgrade the BOS-OMEGA Tri-State Engine into a qubit-inspired probabilistic decision engine.

Important:
This is not literal quantum computing.
It is a quantum-inspired control model where GO, HOLD, and ABORT exist as weighted decision amplitudes before collapsing into one runtime state.

Implement tri-state as:

states:
- GO
- HOLD
- ABORT

Each task starts with a neutral vector:
GO = 0.33
HOLD = 0.34
ABORT = 0.33

Evidence signals update the vector:
- clear user intent increases GO
- safe request increases GO
- complete required inputs increase GO
- missing inputs increase HOLD
- ambiguity increases HOLD
- tool/provider failure increases HOLD
- low confidence increases HOLD
- unsupported factual claim increases HOLD
- unsafe request increases ABORT
- unauthorized action increases ABORT
- illegal instruction increases ABORT
- impossible request increases HOLD or ABORT depending on cause

Normalize scores after updates so GO + HOLD + ABORT = 1.0.

Collapse rules:
- If ABORT >= 0.70, final state = ABORT
- Else if HOLD >= 0.45 and missing inputs/errors exist, final state = HOLD
- Else if GO >= 0.60 and validation passes, final state = GO
- Else final state = HOLD

Store:
- raw evidence signals
- pre-collapse vector
- collapse reason
- final state
- confidence score

Add database table:

tri_state_decisions:
- id
- task_id
- go_score
- hold_score
- abort_score
- evidence_signals
- collapse_reason
- final_state
- created_at

Add frontend display:
- Tri-State vector bar
- GO/HOLD/ABORT score
- evidence signal list
- collapse reason
- final decision badge

Critical rule:
The vector is advisory until collapsed.
Only the collapsed state controls execution.
